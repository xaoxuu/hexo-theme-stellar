## 适用范围

本文说明使用方如何在不修改主题核心文件的情况下覆盖 Stellar 外观。公共令牌的语义和当前默认值见[设计令牌与 CSS 变量](../01-样式系统/design-tokens.md)；本文只记录覆盖入口和边界。

## 覆盖优先级

按以下顺序选择方式：

1. 主题配置：适用于公开的字体、颜色、圆角、背景和主题模式；
2. CSS 自定义属性：适用于布局、间距、字号和需要按断点变化的值；
3. 注入 CSS：适用于站点级覆盖和外部样式；
4. 自定义插件或组件选择器：仅当没有公共入口时使用。

不要为了改变一个公共值复制整段组件 CSS；先查设计令牌页面和源码变量。

## 配置覆盖

常用配置入口包括：

| 配置键 | 用途 |
| --- | --- |
| `style.prefers_theme` | 初始主题模式：`auto`、`light` 或 `dark` |
| `style.font-size.root` | 页面字号基准 |
| `style.font-family.*` | 正文、代码和代码块字体栈 |
| `style.color.theme` / `accent` / `link` | 主题色、强调色和链接色 |
| `style.border-radius.*` | 卡片、图片和横条圆角 |
| `style.leftbar.*` | 左栏背景和背景图 |

实际可用配置以主题 `_config.yml` 为准；已移除的配置不会因为文档示例仍然存在而恢复。

## CSS 自定义属性

主题提供的公共变量包括 `--width-main`、`--side-content-width`、`--gap-base`、`--gap-page`、`--fs-root`、`--fs-content` 和标题派生变量。变量语义、默认值和响应式规则集中见[设计令牌与 CSS 变量](../01-样式系统/design-tokens.md)。

覆盖时优先改变语义变量：

```css
:root {
  --width-main: 860px;
  --gap-base: 12px;
}
```

如果覆盖需要保持响应式，应在相同断点重新声明，而不是用一个固定值覆盖全部设备。公共变量的覆盖会影响所有消费方，提交前检查首页、文章页、Wiki 页和移动端。

## 注入和站点自定义 CSS

使用方可以通过主题支持的 `plugins.*.inject` 入口加载站点 CSS，也可以在站点工程维护自己的 CSS 文件。自定义样式应：

- 放在使用方工程，不修改主题发布包；
- 使用 `var(--theme)`、`var(--card)`、`var(--text-p1)` 等语义变量；
- 记录覆盖目的、作用范围和主题版本假设；
- 避免无必要的 `!important` 和重复组件实现。

## 组件覆盖边界

只有在公共配置、设计令牌和注入 CSS 都无法满足需求时，才覆盖组件私有选择器。覆盖记录至少包含：目标组件、视觉或行为目的、受影响页面、响应式处理和升级检查点。

组件的具体选择器、普通内边距、图标尺寸和阴影值以主题源码为准；这些值不作为本页的稳定接口。

## 验证与故障排查

样式覆盖完成后检查：

1. 生成产物中自定义 CSS 已加载；
2. 选择器优先级和加载顺序符合预期；
3. 明暗主题、移动端和大屏均无溢出或对比度问题；
4. 主题升级后公共变量和目标选择器仍存在；
5. 主题仓库文档变更运行 `python3 docs/knowledge/tools/verify.py`。

样式问题的具体调试使用浏览器 DevTools；知识库记录可复用的原因和契约，不记录一次性调试过程。

## 维护边界

本文是覆盖入口和升级边界的说明，不是 CSS 参考手册。新增公共变量应先更新[设计令牌与 CSS 变量](../01-样式系统/design-tokens.md)，新增组件契约应更新对应领域页面，历史取舍放在 `docs/designs/`。
