# Stellar 主题中文知识库

> 为 Stellar 主题（hexo-theme-stellar）贡献者与 AI 编码工具提供的中文参考资料。

## 目录结构

- `00-总览与安装配置/` ~ `09-高级主题/`——按主题域组织的中文知识库
- `_glossary.md`——术语对照表
- `VERIFICATION.md`——核查与修正记录
- `tools/verify.py`——硬事实核查脚本（用法：`python3 tools/verify.py`）

## 使用方式

- **按域浏览**：从下方领域入口进入，每个领域有 `index.md` 页面索引
- **作为 AI 背景资料**：涉及主题代码、配置或行为问题时，先查阅对应领域再读源码确认

## AI 知识库写作规范

知识库记录设计语义、行为契约和修改依据，不复制完整的实现快照。具体 CSS、模板和 JS 实现以源码为最终事实来源；单次任务的取舍与历史过程放在 `docs/designs/`。

### 信息分层

- `01-样式系统/design-tokens.md` 是公共设计令牌、默认值和响应式档位的权威页面。
- 各领域页面只记录本领域的行为、布局契约、公开配置和关键阈值。
- `README.md` 与 `index.md` 负责导航，不重复业务规则。
- 同一个事实只在一个页面解释，其他页面通过链接引用。

### 设计前置检查

涉及样式、模板、脚本或组件的新功能，先从源码和现有知识库查找可复用定义，再决定是否新增值或接口。检查顺序固定为：

1. 现有配置、设计令牌和 CSS 自定义属性；
2. `_defines/`、`_common/`、`_partial/`、`helpers/`、`utils.js` 和数据服务入口；
3. 现有组件的参数、状态类和生命周期接口；
4. 最后才新增组件私有值或公共接口。

新增定义必须标明语义、作用域、消费方、默认值来源和是否允许使用方配置。跨页面或跨组件能力优先抽取为可复用 partial、helper、mixin 或批量挂载入口；已有功能的局部变体优先扩展既有接口，保持调用方契约不变。

### 定义分类

| 类型 | 判断标准 | 文档要求 |
| --- | --- | --- |
| 公共设计令牌 | 多个组件消费，或构成主题级视觉/布局契约 | 记录唯一名称、语义、来源、默认值和作用范围 |
| 组件契约 | 组件参数、公开配置、状态类、DOM/API 入口 | 记录输入、输出、状态转换、复用方式和降级行为 |
| 运行时状态 | 生命周期、观察器、动画帧、请求状态等闭包变量 | 只记录会影响交互、性能、兼容性或验收的行为 |
| 实现内部值 | 着色器中间值、一次性布局值、局部算法参数 | 以源码为事实；只有影响设计决策或兼容性时才记录 |

例如，`source/css/_custom.styl` 中的 `$gap-*` 属于公共令牌；Galaxy 插件的 `params` 属于功能参数；`stellar.galaxy.mountAll(canvases)` 属于可复用客户端入口；动画帧和观察器变量属于运行时状态。文档应解释这些定义的职责，不复制完整实现。

### 数值保留规则

保留会影响 agent 决策、实现、兼容性或验收的数值：公共令牌、行为阈值、布局契约、公开配置默认值和兼容性特殊值。普通选择器的 `padding`、`margin`、`font-size`、图标尺寸和一次性实验值，只有在具有上述作用时才记录。

保留数值必须说明语义和作用范围，例如：

```md
- `gap-base: 16px`：组件内部基础间距，供多数组件复用。
```

可能变化的值标记为当前默认值，并链接源码定义；修改公共令牌时只更新权威页面和受影响的行为契约。知识库改动后运行 `python3 docs/knowledge/tools/verify.py`。
