# 修复 ScrollReveal 对吸顶/固定组件可见性误判

> 日期：2026-08-09

## 背景

带锚点打开文章页（如 `/blog/20200823/#在线演示效果`）或浏览器恢复滚动位置时，右栏「本文目录」等吸顶组件有概率不显示，停留多久都不会出现，只有向上滚动到顶部才出现。

根因在 ScrollReveal 的可见性判断：它按元素的**文档坐标**（`offsetTop`/`offsetHeight`）判断是否进入视口，对 `position: sticky/fixed` 元素没有特殊处理（仅对 `fixed` 有例外分支，且该分支基于计算样式，对 sticky 无效）。侧栏组件位于 `position: sticky` 的 `aside` 内、TOC 组件自身也是 sticky，其文档坐标始终在页面顶部附近；当页面初始化时已经滚动到中部（锚点跳转/滚动恢复），ScrollReveal 会判定这些组件「不可见」并保持隐藏，只有滚动回顶部让文档坐标进入视口时才触发 reveal。

加载时机决定了问题是否出现（ScrollReveal 从 CDN 异步加载，与浏览器的锚点跳转/滚动恢复存在竞态），因此表现为「概率性」。

## 方案

在 `layout/_plugins/scrollreveal.ejs` 初始化时，把自身或任一祖先为 `sticky`/`fixed` 的元素按「最近的吸顶/固定祖先」分组，每组以该祖先作为 ScrollReveal 的 `container` 单独 reveal（右栏、左栏各自成队）；其余元素维持默认行为。

理由：

- ScrollReveal 支持 `container` 选项，可见性按容器的滚动位置判断；把吸顶容器本身作为容器后，容器与元素始终相交，可见性恒成立，入场动画（透明度 + 位移 + interval 错峰）完整保留。
- 吸顶/固定容器内的组件始终在视口内（或由容器自身的显隐逻辑控制），本来就不依赖主文档滚动驱动 reveal。
- ScrollReveal 4.0 通过 CDN 加载、为压缩产物，无法在主题侧修补其可见性算法；在插件层按容器分组是改动最小且可靠的方式。

## 影响范围

- 修改文件：`themes/stellar/layout/_plugins/scrollreveal.ejs`
- 行为变化：左/右栏侧栏组件（TOC、作者卡片、最近文章、标签云等）在任何加载方式下都可见，并保留入场动画；主区内容（文章、卡片、页脚等）的 reveal 行为不变。
- 不涉及主仓库（xaoxuu.com）内容与配置。

## 验证

- 带锚点加载 `/blog/20200823/#在线演示效果`：右栏 TOC 立即播放入场动画并保持可见，滚动到任意位置均不隐藏。
- 普通顶部加载、刷新（含滚动位置恢复）均正常，入场动画表现与修复前一致。
- 桌面（sticky）与窄屏（fixed 侧栏）两种布局下均验证。
- `npm run g && npx gulp minify` 全量构建通过。
