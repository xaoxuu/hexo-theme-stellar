# 侧边栏艺术渐变背景方案

## 1. 问题与目标

现有 Glass 左栏只支持图片或纯色背景。站点不希望引入图片资源时，纯色无法获得图片经过重度模糊和滤镜后的层次感。本切片新增浅色、深色两套四颜色调色板，由 CSS 组合静态艺术渐变。

成功标准：用户只配置色相，不需要手工维护两套颜色；不请求背景图片也能得到多层柔和色块；现有图片、纯色与 Card 表面保持兼容。

## 2. 技术方案

### 复用入口

- `CONFIG_SCHEMA` 继续作为类型、默认值、错误、默认 YAML、Reference 和字段审计的唯一所有者。
- `source/css/_custom.styl` 继续把 `appearance.backgrounds.sidebar` 投影为 Stylus 变量。
- `.l_left .sidebg` 继续承载背景、模糊和透明度；`.leftbar-container:before/:after` 继续承载玻璃高光与遮罩。图片分支保留既有饱和度滤镜。

### 新增契约

- `type` 默认 `gradient`，可选 `gradient` / `image` / `color`，显式决定唯一背景分支。
- `gradient.light/dark` 各自必须恰好包含四个合法 CSS 颜色，顺序为基础色、左上、右中、左下；两种模式可独立覆盖。
- 默认调色板直接使用 HSL：浅色为 `210 32% 84%`、`188 44% 84%`、`12 64% 73%`、`35 100% 82%`，暗色为 `210 16% 48%`、`188 18% 50%`、`12 30% 42%`、`35 36% 49%`。Stylus 不再推导饱和度或亮度。
- 默认使用 `surface: glass`、留空的 `image:`、`opacity: 1`、`backdrop.radius: 100px` 和 `backdrop.overlay: var(--bg-a50)`；空值在运行时仍为 `null`。
- 三种类型不隐式降级到其它分支；启用图片只需 `type: image` 和非空 `image`。渐变暗色分支不应用图片专用的 0.75 透明度系数。
- 基础色写入 `background-color`；左上和右中使用径向渐变，左下使用锥形渐变。渐变使用 `blur + opacity`，不叠加图片专用的 `saturate`，确保主题设定的 HSL 饱和度不被二次改变。
- 不支持渐变的浏览器仍显示基础色；`surface: card` 继续隐藏 `.sidebg` 和覆盖层。

不需要修改 `layout/`、`source/js/` 或 `languages/`，不新增依赖和动画。

### 视觉校准（2026-08-26）

- 推荐示例与 xaoxuu.com 使用 `[210, 188, 12, 35]`，保留线上旧版默认侧栏图片的冷灰白铺底、顶部青蓝雾光、中段珊瑚色和底部砂金色关系。
- 饱和度和亮度由主题统一控制，用户只承担色相选择；浅色模式保持轻柔明亮，暗色模式使用低饱和深色底。
- 三个色块使用独立的 `background-size` 与定位，控制在约半栏宽、三分之一栏高；保留径向、径向、锥形三层结构，但避免单层光晕覆盖大半个侧栏。
- 显式 `type` 取代空数组开关和渐变优先级；暗色透明度规则和 Card 行为不变。

## 3. 影响范围

- 公开配置：新增 Theme Schema 背景类型与浅色/深色调色板字段。
- 样式：扩展 `_custom.styl` 与 `sidebar.styl`。
- 测试：配置解析、结构化错误与 CSS 编译回归。
- 文档：侧边栏系统、深色模式、设计令牌、`VERIFICATION.md`、公开 Wiki 和自动 Reference。

## 4. 验证方式

- 按 F1 运行 Schema 生成/检查、Schema/Appearance 定向单测、知识库核查与规范引用检查。
- 本地抽查桌面与移动端深浅模式；本切片不运行全仓、tarball 集成、M10 或人工验收包。
- 对生成 CSS 检查两套 HSL 输出、多层渐变、显式图片/纯色分支与 Card 隐藏规则。
