# README 重构：充分体现主题优势

## 1. 问题与目标

- 要解决的问题：现有 README 卖点罗列较为平淡，未充分体现主题「简约商务美学 × 强大综合能力」的双线定位，部分事实（展示墙站点数）已过期。
- 参考分析：[Stellar 为什么没能进入 Hexo 主题头部](https://xaoxuu.com/blog/20260815/)——定位错位与「功能多、但复杂」的感知是核心短板，要求 README 首屏用一句话讲清「博客 + 知识库一体」，并提供低门槛起步路径。
- 成功标准（可验收的行为）：
  - `README.md` 重构为四组特性结构（内容系统 / 标签组件 / 动态数据组件 / 体验与性能），每组附文档链接；
  - 首屏一句话定位「博客 + 知识库一体」，并给出「可当轻博客使用、其他系统按需启用」的低门槛表述；
  - 卖点强调四系统 + 动态数据组件的一体化整合与开箱即用，不堆砌功能数量；
  - 新增 `README_EN.md`，与中文版结构、链接一一对应，顶部语言互链；
  - 移除过期事实（「30 个站点」计数），环境要求与知识库 `installation.md` 一致；
  - 不修改代码、配置、知识库与 `VERIFICATION.md`。

## 2. 技术方案

- 实现思路：纯 Markdown 文档重写，不涉及构建与脚本改动。
- 涉及文件：
  - `README.md` — 中文版重写
  - `README_EN.md` — 英文版新增（完整翻译，同结构同链接）
  - `docs/designs/2026-08-16-readme-refactor/` — 本方案文档

## 3. 影响范围

- 对外行为 / 配置项 / 兼容性影响：无代码、无配置、无构建变更；npm 包发布内容新增 `README_EN.md`（`.npmignore` 未排除，随包发布）。
- 需要同步的知识库页面与文档：无（`README.md` 非 `verify.py` 扫描对象，知识库内容不变化）。

## 4. 验证方式

- 逐条验证两个 README 中全部外链可达（文档站、GitHub、npm、示例仓库、Star History、deepwiki）。
- 对照 `docs/knowledge/` 复核事实表述（四大内容系统、标签组件、数据服务、环境要求）。
- 运行 `python3 docs/knowledge/tools/verify.py` 回归确认知识库核查通过。
- 检查 GitHub Markdown 渲染（语言切换、徽章、锚点、表格、代码块）。
