# mbti 人格特征标签设计方案

> 日期：2026-08-10

## 问题与目标

为 Stellar 增加一个纯静态的 MBTI 人格特征展示标签：用户传入人格类型、五个维度的百分比与可选的 16Personalities 档案链接，渲染为「类型名 + 五条两端标签进度条 + 档案链接」的卡片。

约束：

- 不请求外部接口，数据完全由用户提供（避免构建期网络依赖与跨域问题）
- 进度条视觉复用 `okr` 标签的细条圆头样式
- 配色采用 16Personalities 官方四组角色色
- 所有展示文案放入 `languages/`，随站点语言切换

## 技术方案

### 标签接口

```md
{% mbti INTJ-T 93-72-78-83-51 %}
{% mbti INTJ-T 93-72-78-83-51 https://www.16personalities.com/ch/档案/9d09a4297ffa2 %}
```

- 参数 1 `type`：人格类型代码（必填），决定标题与配色，识别失败时使用默认色并告警
- 参数 2 `scores`：五个百分比（必填），`-` 分隔，顺序固定为 `energy-mind-nature-tactics-identity`（精力 → 认知方式 → 决策方式 → 生活方式 → 身份），各为 trait 侧百分比；缺位补 0、非法值钳制到 0–100、多余忽略
- 参数 3 `url`（可选，`url:https://...` 形式）：完整档案链接或纯档案 ID（自动补全中文站链接）；传入时标题行变为可点击链接（新标签页打开，hover 显示下划线），不传则标题为纯文本
- 参数 4 `image`（可选）：标题上方横幅图片地址，铺满卡片宽度、高度自适应；不传则不显示
- 进度条方向：两端标签顺序固定（精力 外向/内向、认知方式 直觉/观察、决策方式 思考/感受、生活方式 判断/展望、身份 坚定/动荡），从类型代码推导偏向侧（E/I、N/S、T/F、J/P、A/T），进度条从偏向侧填充；身份维度缺失 `-A/-T` 时默认「坚定」并告警

### 实现

- `scripts/tags/lib/mbti.js`：标签实现，注册名为 `mbti`（单行标签）。位置参数通过 `ctx.args.map` 解析；文案通过渲染上下文 `this.__` 读取（兜底 `ctx.theme.i18n.__(ctx.config.language)`）；类型名与维度两端标签来自 `languages/tag_plugins.mbti.*`
- `source/css/_components/tag-plugins/mbti.styl`：卡片容器 + 五维进度条，进度条结构复刻 `okr.styl`（`.progress` 细条、`.fill` 圆头圆点）；容器内联 `--theme` 为类型对应色值
- `languages/{en,zh-CN,zh-TW}.yml`：新增 `tag_plugins.mbti`（底部链接文案、16 型名称、5 维两端标签）
- 颜色映射到主题内置色板（容器与维度行内联 `--theme` 与 `--theme-a30`）：顶部标题与卡片边框按 16Personalities 角色组着色（分析家紫/外交家绿/守护者蓝/探险家黄），五维进度条按维度着色（energy 蓝/mind 琥珀/nature 绿/tactics 紫/identity 红），主导侧用主题色填充、轨道用 `--theme-a30`；卡片背景使用普通卡片底色，卡片内文字固定使用 `text-p1` / `text-p3`，不随彩色主题变化

## 影响范围

- 新增：`scripts/tags/lib/mbti.js`、`source/css/_components/tag-plugins/mbti.styl`、`languages/*.yml` 的 `tag_plugins.mbti` 段、本文档
- 修改：`scripts/tags/index.js`（注册标签）
- 不影响现有标签与站点配置；无需新增依赖

## 验收标准

- `npm run g && npx gulp minify` 构建通过
- 中/英文站渲染文案正确，标题为「我的 MBTI 人格：INTJ-T（建筑师）」格式
- 五条进度条方向与百分比正确，进度条按维度显示专属颜色，顶部类型名按角色组着色
- 不带 URL 时标题为纯文本；带 URL/纯 ID 时标题可点击跳转且新标签打开
- 明暗主题下进度条与文字可见
