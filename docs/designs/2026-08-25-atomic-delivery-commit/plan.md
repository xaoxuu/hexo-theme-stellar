# 执行计划

## 实施步骤

1. [x] 在主题规范、双份开发 Skill 与 issue 流程中定义提交前文档同步核验和单一交付提交。
2. [x] 删除 SHA 台账、发版登记脚本及单测，更新 `npm run check` 与发版说明。
3. [x] 更新设计模板和知识库修正记录，使后续任务在提交前完成文档语义核验。
4. [x] 运行完整检查并记录最终结果；性能降幅通过门槛，但本机 gzip 输出与仓库 fixture 存在平台级字节差异。

## 风险与回退

- 风险：删除 SHA 台账后失去重复的人工索引。Git 历史、CHANGELOG 与 GitHub issue 评论分别保留提交事实、发布摘要和交付证据，无需仓库内副本。
- 风险：硬事实脚本无法判断文档语义是否完整。Agent 必须逐项核对最终功能 diff，发现遗漏时停在提交前。
- 回退：恢复登记脚本、单测、表格和规范引用；不会影响主题运行时数据或公开接口。
