# 执行计划

## 实施步骤

1. [x] 补充版本文件准备逻辑的回归测试并确认旧实现无法满足。
2. [x] 实现原子版本文件准备，将安装知识库纳入备份、diff、暂存与恢复范围。
3. [x] 将质量检查移动到版本文件准备之后，并同步安装知识库与发版指南。
4. [x] 执行单测、完整检查和知识库核查，记录验证结果。
5. [x] 提交并仅推送主题 `main`，确认远端 CI 全部通过。
6. [ ] 更新并本地提交主仓库子模块指针。

## 风险与回退

- 风险：文档结构变化后旧版本号无法安全定位。处理：写入前要求至少匹配一次当前包版本，否则中止且不修改任何文件。
- 风险：最终态检查失败留下半更新工作区。处理：所有受管文件先备份，失败统一恢复。
- 回退：修复提交可独立回退；不会触发 npm 分支发布，也不修改既有 1.43.0 tag/Release。
