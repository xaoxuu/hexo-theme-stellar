# Stellar Theme Dev

仓库根 `AGENTS.md` 是工程规范的唯一权威；本 skill 只编排一次任务的执行顺序，不复制门禁细节。

## 1. 定界

- 检查工作树，确认用户目标、受影响契约和可用证据，只读取相关默认配置、源码、Schema 与测试。
- 按方案与受影响调用链识别 `AGENTS.md`「兼容来源门禁」的适用范围；涉及外部兼容时锁定发布基线并定位来源证据。
- 按 `AGENTS.md`「验证门禁」选择 F0–F3。
- 需要持久化方案或触发复用门禁时，按 `AGENTS.md` 的对应章节执行；方案只进入获准操作的 GitHub issue。

完成条件：范围、所有者、验证级别和直接证据均已明确，待核对的适配与扩展协议已定位。

## 2. 实现

- 复用现有结构，直接表达当前最终候选；新增或调整测试时执行 `AGENTS.md`「测试保留门禁」。
- 配置声明、数据形状、接口或协议迁移完成后，逐项核对剩余声明与消费者，按 `AGENTS.md`「兼容来源门禁」清理失去用途的接口及支撑机制。
- 机器契约随实现保持当前；发布快照按文档规则延后。

完成条件：实现覆盖目标契约，本次新增或调整的仓库测试已收敛到长期入口；受影响适配与扩展协议均已有保留依据或清理结果。

## 3. 验证

- 从最接近改动的证据开始，严格按 `AGENTS.md`「验证门禁」升级；不要因路径、文件数量或阶段标签自动扩大验证。
- 按最终受影响范围复核上述逐项结果与调用链，确认满足 `AGENTS.md`「兼容来源门禁」的完成条件。
- 如有方案 issue，保留可供获准更新的实际命令与结果。

完成条件：每个受影响契约都有一项通过的直接证据并停在最低充分级别；适用门禁的完成条件已逐项核实。

## 4. 交付

- 按 `AGENTS.md`「交付门禁」处理工作区、提交、推送和 issue 权限。
- 普通开发不提前维护发布快照；用户明确要求发版时进入 `docs/guides/release-process.md`。

完成条件：验证结果和改动状态已清楚汇报；所有外部写入均有用户授权。
